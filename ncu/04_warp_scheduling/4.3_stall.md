# 4.3 Warp Stall：先问为什么等，再问是否拖慢整个 Kernel

配套：[第四课讲义](lec04.md) · [4.1 尾部效应](4.1_tail.md) · [4.2 调度器统计](4.2_scheduler.md) · [实验 04](lab04.md)。本文补足阅读等待原因前需要的机制，不要求先背 NCU 的英文状态名。以下时序和数字均为教学模型，不是本次实测。

## 1. 从两条指令认识“等”

Kernel 是由 GPU 线程执行的函数；线程组成 Block（线程块，也叫 CTA），本次全部块组成 Grid。块由 SM（GPU 上执行块的硬件单元）接收，其中每 32 个线程组成一个 Warp。Warp 的执行状态和资源已分配、尚未完成时叫 **Active（驻留）**。SM 内的子分区叫 SMSP，Warp Scheduler（Warp 调度器）管理其中的 Warp。

看一个线程的操作：先从数组取数 `x=in[i]`，再算 `y=x*2`。第二步必须用第一步的新结果，不能读旧的 x。这叫**数据依赖**；具体是 RAW（Read After Write，先写出结果，再读这个结果）。下面把这两步写成示意机器指令，GPU 原生机器指令称为 SASS：

```text
LDG  R4, [R2]       ; 从 R2 指向的全局地址读取，结果放入寄存器 R4
FMUL R5, R4, 2      ; 读取 R4，计算乘法，结果写入 R5
```

寄存器是保存线程中间值的片上小存储，`[R2]` 表示使用 R2 保存的地址，而不是把 R2 的数值直接拿来相乘。LDG 是全局读取，FMUL 是浮点乘法；本片段不表示某架构的完整合法指令格式。产生 R4 的 LDG 叫 **Producer（生产者）**，使用它的 FMUL 叫 **Consumer（消费者）**。

**Issue（发射）**表示调度器把指令交给执行路径，不表示结果当场可用。LDG 发出后，FMUL 可能仍须等 R4 返回。**Scoreboard** 是跟踪某些未完成操作及其依赖的硬件机制：概念上像给 R4 标上“新值尚未可用”，阻止消费者过早读取。固定延迟计算、内存返回和同步并非全由一套统一机制实现，NCU 会区分它们。

Warp 下一条指令输入和资源条件允许参与发射时叫 **Eligible（就绪）**；实际被选中发射时叫 **Issued**。因为条件未满足而不能发射叫 **Stall（等待/阻塞）**。等待 FMUL 的 Warp 仍是 Active，不是被逐出 SM。第三课算资源允许驻留多少；第四课才研究运行时有没有填满、驻留之后能不能推进，不能把这两层混成一个“利用率”。

## 2. 三种常见机制：结果未回、入口拥堵、参与者未到

### 2.1 已经发出，等待结果：Scoreboard 与 Wait

**L1TEX** 是 SM 附近处理 Global（全局）、Local（每线程私有地址空间）、Texture/Surface（带专用寻址或取样功能的访问）等操作的硬件单元/路径，不只是 L1 缓存容量的名字。NCU（Nsight Compute，单 kernel 性能分析器）的 **Long Scoreboard** 表示依赖此路径的操作尚未完成。例如上面的 FMUL 在等 LDG。名字中的 Long 不证明一定访问了 DRAM，更不证明 DRAM 带宽已满。

**MIO（Memory Input/Output）**是处理另一组指令的输入输出路径，常涉及 Shared Memory（同块线程共享的片上数组），也涉及部分特殊数学或控制操作。**Short Scoreboard** 表示相关依赖未满足。例如先从 shared 数组读 x，下一条加法立即用 x，数据未到时就可能等待。Long/Short 按路径分类，不是把所有等待按统一周期数阈值切成两半。

Shared Memory 为何也可能慢？它分为多个可并行服务的 **bank（存储分组）**。常见模型把连续的 4B 字轮流放到 32 个 bank；B 是字节，`float` 占 4B。若一次 Warp 访问中，两个线程要读同一 bank 的两个不同字，便需要分轮服务，这叫 **bank conflict（bank 冲突）**。若读取完全相同的字，则可把同一份数据广播给多个线程，通常不构成这种冲突。冲突可能增加结果等待，但 Short Scoreboard 并不自动证明有冲突。

内存单元的一个 **Request** 是提交的访存工作项；一个 **Wavefront** 是内部一轮能处理的工作包，多个包可能需要依次服务。例如同 bank 两个不同字，在简化 shared 模型中需两轮。Wavefront 不是 Grid 的 Wave（全 GPU 块容量估计），也不是 AMD 用来称呼线程执行组的 wavefront；在此处它更不等于整条指令的延迟周期数。第五、六课会保留这些不同层次分别计算。

**Wait** 常用于固定时延的执行依赖，例如 `acc=fma(a,b,acc)` 中下一次乘加等待上一次 acc。FMA 是融合乘加，把乘法和加法作为一个操作、只做一次舍入。不能把所有算术等待都称为 Long Scoreboard。

### 2.2 新工作进不去：Throttle

**管线**把一项操作分阶段处理，使不同操作有机会重叠；**队列**暂存等待处理的指令或请求。队列或执行资源不能再接收新工作时，下一条指令可能遇到 **Throttle（入口/资源受限）**，与已发出操作的结果等待不同。

理解这层区别后再读名称：LG Throttle 关联 Local/Global 指令入口压力；MIO Throttle 关联 MIO 操作入口压力；TEX Throttle 关联纹理路径入口压力；Math Pipe Throttle 关联所需数学执行管线暂不能接收操作。例如大量窄读取可能使入口很忙，即使 DRAM 字节速率不高，也可能受请求数量限制。

这些状态名的适用范围依架构和 NCU 版本而变。不能由“Throttle 高”单独证明该硬件已达到可持续吞吐上界，仍需相应管线指标和对照实验。

### 2.3 等其他执行者：Barrier 与 Membar

假设线程 A 往 shared 数组写数，线程 B 要读取它。它们能够访问同一数组，不代表 B 一定晚于 A 执行；这种先后必须由程序建立。**Barrier（会合屏障）**让规定的参与线程到齐后再继续；`__syncthreads()` 用于同块线程会合，也为相应的前后内存访问提供可见性保证。

一个块有 8 个 Warp，7 个先到会合点、最后一个还在算，前 7 个会等待，通常仍是 Active。这可能让 Eligible 变少，但不直接等于驻留数下降。应查同步之前的工作分配，不能删掉保证正确性所必需的同步。

**Fence（内存栅栏）**约束调用线程前后内存操作的顺序及相应可见性，不要求别的线程都到同一地点；NCU 的 **Membar** 与此类约束和未完成内存操作有关。Fence 不是 Barrier 的同义词，也不能单独替代完整的跨线程数据交接协议。

## 3. 一个 Warp 在等，不等于调度器没有工作

**Latency（延迟）**是一项操作从指定起点到结果可用等多久；**Throughput（吞吐）**是每单位时间处理多少工作。周期是硬件时钟的一拍，不是固定多少秒。

假设一个教学调度器每周期最多发一条指令，相关乘加的结果 4 周期后可用。W0 在周期 0 发出 A0，最早周期 4 发 A1；如果 W1、W2、W3 的独立工作在周期 1、2、3 发射，就填上了空档，而没有缩短 W0 的单次延迟。这叫用其他 Warp 提供的线程级并行 **TLP** 隐藏等待。也可在同一 Warp 中准备互不依赖的多个累加器，这叫指令级并行 **ILP**。

如果 W0、W1 都已就绪而本周期只选 W1，W0 是 **Not Selected**：它不是缺数据，而是没轮到。只要调度器能持续提供有效指令，这种富余候选通常不必消除。

## 4. 先看统计对象和分母，再读百分比

NCU（Nsight Compute）是单 kernel 性能分析器；Section 是相关指标组，metric 是具体计数或派生指标。不要把所有百分比当成“占总时间多少”。

例如观察一个调度器 4 个周期，4 个驻留 Warp 每周期都有 3 个在等、另一个成功发射：累计有 `3×4=12 Warp-cycles` 的等待，却只有 4 个经过周期，且每周期都发生了发射。Warp-cycle 是一个 Warp 在一个周期贡献一次状态；不同 Warp 的状态可同时累计。**Issue Active** 关注发生发射的周期，而不是这些 Warp-cycle 的和。

NCU 的 WarpStateStats 可能把状态按每条已发射指令等分母归一化；Source 页面也可能使用 **PC Sampling**：间隔抽取 Warp 的 PC（程序计数器，即下一指令位置）和状态，形成样本分布，而非逐周期记录所有 Warp。消费者等待 R4 时，热点可能落在 FMUL，而不是 LDG。`65% Long Scoreboard Samples` 因而不等于“65% kernel 时间都在等 DRAM”。All Samples 与 Not-issued Samples 也不保证来自同一次采集遍次，不能随意相减。

`sm__` 指 SM 层，`smsp__` 指子分区层；`.sum` 是求和，`.avg` 是实例平均，`per_cycle_active` 按该硬件的活动周期归一化，`per_cycle_elapsed` 按经过周期归一化。百分比后缀还可能相对硬件参考峰值。小 Grid、空闲 SM 与尾部如何进入分母取决于具体指标，不能用“用了多少块/全 GPU 能放多少块”直接代替 Achieved Occupancy。

## 5. 从症状走到可检验的原因

先确认采到的函数、输入和启动规模正确，再按以下顺序推理。Duration 是 kernel 执行时间；Source/SASS 页面把计数或样本关联到代码/机器指令。表中的步骤是调查方向，不是未经实测的结论。

| 先观察的现象 | 机制问题 | 再找什么证据 |
|---|---|---|
| 实际驻留少 | 工作块不够，还是资源上限低、Warp 已结束？ | Grid、资源预算、块寿命与尾部；不要直接怪 Stall |
| Active 多，Eligible 少且发射不足 | 驻留工作为什么不能推进？ | 结果依赖、请求入口、同步参与者进度 |
| Long Scoreboard 高 | 哪次已发出的读取结果未到？ | 消费者沿寄存器依赖回溯生产者，再看各级流量和并发 |
| Short Scoreboard 高 | 哪个 MIO 结果未到？ | shared 地址、实际/理想 Wavefront、其他特殊指令 |
| Barrier 高 | 谁还没有到齐，之前在做什么？ | 同步前的负载分布和必要的正确性条件 |
| Not Selected 多、发射持续 | 候选工作是否已足够？ | 执行管线吞吐、无效指令和总时间，不盲目增加 Warp |

自测：一个 Warp 在等 shared 读取，另一个已经发射；能否把第一个的等待全记为 GPU 浪费时间？不能。再问：如果增加独立链后时间缩短，能否只凭一个 Stall 百分比下降就证明原因？也不能；循环指令数、寄存器、驻留能力都可能同时变化，需要保留基线并检查替代解释。
