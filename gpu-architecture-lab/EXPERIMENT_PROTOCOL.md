# 实验记录规范

每项实验沿同一条链写记录：**规范语义与正确性 → 预测硬件行为 → CUDA 源码与输入 → PTX/SASS → 动态测量 → 解释与边界**。首次编辑源码前先写假设；基线与候选实现使用明确的对照条件，不混用结果。所有当前结论都应能回到相应命令、日志和报告。本实验室将每个动作的脚本与日志放在同一 `commands/<action>/` 目录，源码和构建产物另行共享；不使用自动归档或快照。

## 实验页模板

新实验的 `README.md` 或 `analysis.md` 采用以下栏目；不适用的栏目写明原因，不留含糊空白。

| 栏目 | 必须写明 |
| --- | --- |
| 问题与预测 | 一个问题、一个主要变量、预期曲线或趋势、推理所用的地址/warp/资源模型。 |
| 对照条件 | GPU/驱动/Toolkit/分析器版本、目标架构、编译参数、输入大小、grid/block、重复次数和计时范围。 |
| 正确性 | CPU 参考或解析结果、误差标准、边界输入、地址/类型/对齐、对象生命周期；并发场景的参与者、order/scope、发布与复用协议、进展条件；sanitizer 的具体工具、版本与状态。 |
| 静态产物 | `.cu`、PTX、cubin/SASS、寄存器/共享内存/stack/spill；写明哪些是编译推断。 |
| 动态测量 | 原始时间、统计口径、Nsight Systems 时间线、可用时的 NCU 指标；指标名和单位随工具版本保存。纯功能实验明确写“未计时”，不补性能结论。 |
| 解释 | 观察是否支持预测、其他可能原因、下一次要改变的唯一变量。 |
| 证据索引 | 指向 `commands/<action>/<variant>.log` 中的命令、参数、原始输出和退出码，以及 `build/<variant>/` 中的对应产物与报告。不使用哈希、源码快照或自动历史归档。 |

## 开始前：构建、能力与正确性

没有统一构建或测试入口。进入目标子专题，核对其 `README.md`、脚本动作、默认参数与输出目录；不从其他专题照搬不存在的动作目录。原微架构规划尚无实现的部分，先写实验设计，不把规划命令描述成已有工具。

- 采集本次设备、compute capability、驱动、Toolkit、工具版本及可见设备选择。脚本的 `CUDA_ARCH=sm_XX` 与 CMake 的 `CMAKE_CUDA_ARCHITECTURES=XX` 不是同一格式；目标以设备和编译器共同支持为准，`sm_89` 仅是历史环境示例。
- 为高级路径分别列出 API/头文件版本、PTX 版本、原生 target、运行属性和启动条件。普通 `sm_90` 不等于 `sm_90a`；cluster、system 原子、Tensor Core、异步事务与 `setmaxnreg` 不能用一个统一的“支持 CUDA”标记代替。
- 编译、原生 cubin 执行和 PTX JIT 是独立验证项。能力不足、缺工具、驱动 JIT 失败都保留原始错误，不删检查、不换成空指令后报告通过。
- 正确性覆盖单元素、非整 warp/block/tile、尾部和多轮缓冲复用等适用边界；空输入若 API 或框架不支持，应明确拒绝策略。检查每次 CUDA API、launch 错误和必要完成点的异步错误。
- 有共享数据时先给出 happens-before 或所有权推导，明确 barrier/mask 参与条件以及读者完成后才能覆盖的规则。`volatile`、缓存提示、`asm volatile` 和一次数值 PASS 都不能替代同步；scope 也不保证 block 同时驻留。
- `memcheck`、`racecheck`、`synccheck`、`initcheck` 按问题和工具支持选择；racecheck 的主要 shared-memory 检查不能证明任意 global 跨 block 协议。零报告、工具不认识某条路径与隔离后通过必须分别解释。
- 故意越界、竞态、非法参数等反例在独立动作或进程中运行，写明预期错误与退出码；不进入正常计时基线，不把预期非零当作正常路径通过。

模型与推导方法见 [ARCHITECTURE.md](ARCHITECTURE.md)，工具职责见 [tools](tools/README.md)。

## 测量时统一遵守

- 同一组对照使用相同输入和正确性定义；先确认功能正确，再比较时间。
- 将初始化、分配、主机设备拷贝、预热、kernel 与同步的计时范围分别写清。CUDA event 的一批启动平均时间与 profiler 报告的单 kernel GPU 时间不是同一指标。
- 一组测量做多次重复，当前动作日志中记录该组逐次原始数值与汇总统计，不只保留最快一次。反复调用同动作同配置会覆盖该动作日志，不能用它充当跨调用的历史存储；需比较的参数组应在同一动作中完整记录，或使用确实不同的编译配置，不能假定脚本自动保留所有对照。
- 记录“有效带宽”的分子定义。实际 DRAM 字节、L1/L2 命中或 bank 冲突必须有硬件计数器证据。
- 用相同架构和编译选项比较 PTX/SASS；指令行数与动态执行次数、带宽或耗时不能直接等同。修改内联 PTX 或测量循环后必须检查目标指令、依赖链及计时区间仍然存在；静态解析失败要调查，不能忽略后继续引用性能数字。
- roofline 明确 FLOP 定义、数据类型/累加精度、所选内存层级、实际或估计字节及带宽上界来源；算法字节不能冒充 DRAM 计数。延迟链和吞吐实验分开，`clock64` 周期不能未经频率和计时范围分析直接换算为固有指令延迟。
- 异步实验分开记录 API 提交、GPU 工作跨度与端到端完成时间；多流终点必须覆盖全部参与流。Graph 设置成本与 replay 分开，copy/compute 重叠用实际活动或适用的硬件证据支持，不能仅靠 event 区间相交。
- 分析器可能重放 kernel 或改变执行环境；将普通运行基线与分析器下的时间分开。
- 工具缺失、权限不足或指标不支持时，状态写 `SKIPPED`/`UNAVAILABLE` 并保留错误输出；未测数据不填 `0`。

## 目录、历史证据与状态

每个专题自包含：文档、共享源码、`commands/<action>/run.sh` 和 `build/<variant>/` 位于专题内。每个动作有独立脚本及同目录的 `<variant>.log`，不能保留万能分派器再用薄包装转调。公共层只提供底层执行、日志、锁和产物检查；具体命令、验证和能力检查由各动作直接表达。

先显式运行 `commands/compile/run.sh`。后续执行/检查动作只复用成功产物，缺失即报错，不隐式构建。更改源码、头文件、工具链或选项后主动重新编译；没有哈希、自动依赖追踪或日志失效机制。正负编译契约实验独立存在，每次实际运行探针并匹配诊断，不把工具故障当作预期拒绝。不同架构和编译模式不能混用产物。

日志记录实际命令、输入参数、stdout/stderr、逐步及总退出码。重跑仅覆盖同动作同配置日志，失败/跳过也保留；不保存参数调用历史，不复制源码或脚本。检查器临时步骤输出位于同动作目录，退出后清理。锁、失败产物和异常退出边界见 [RECORD_LAYOUT.md](RECORD_LAYOUT.md)。

既有 `results/README.md` 索引历史配置、动作、参数和状态；原始日志和报告保持原样，当前脚本不写入这些历史日志。`HISTORICAL IMPORT` 不是本轮实测，旧数值不转引为新结果。新的动作日志也不能单凭存在就视为当前源码验证，报告必须核对编译与运行条件。迁移入口见 [MIGRATION.md](MIGRATION.md)。

| 状态 | 含义 |
| --- | --- |
| `PLANNED` | 只有假设和实验设计，没有执行。 |
| `COLLECTED` | 有原始输出，但正确性或测量条件尚未核对。 |
| `VERIFIED` | 正确性、条件、日志和解读均已核对。 |
| `SKIPPED` | 工具或硬件不可用，明确记录原因。 |
| `FAILED` | 命令失败，保留退出码和原始错误。 |

上表用于汇总，不重写旧脚本的原始状态或退出码；退出码（例如 77）按对应专题定义解释。报告同时区分规范语义、模型推导、静态观察、历史记录与本次实测。只有完成新实验并核对证据后，才把 [学习路径](LEARNING_PATH.md) 中相应项目改成已完成；局部用例通过不代表整个里程碑或全部架构路径通过。
