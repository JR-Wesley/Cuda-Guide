# CUDA 程序分析与优化

围绕用户当前的程序和问题选择工作深度。简单的局部解释或修复直接完成；只有判断受编译、执行或测量影响时，才展开相应层次。用户的明确范围与现有授权优先。

## 定位问题

- 先按工作区 `AGENTS.md` 找到目标项目，再读相关源码、构建入口和专题文档。只追本题需要的函数、调用路径、数据布局与输入；历史记录是证据，不是当前源码或当前机器状态。
- 区分本次任务是实现、机制解释、正确性故障还是性能问题。缺少关键输入会实质改变结论时才询问；其余条件明确假设并继续。
- 解释具体实现时从源码和实际配置出发。需要低层证据时，沿同一 kernel、同一架构和编译选项追到 PTX、cubin/SASS；只在必要时查看 Runtime/Driver 调用及硬件指标。源码意图、编译产物和实际执行可能不同。

## 调查与改动

- 正确性故障先找可观察的失败、边界条件和异步错误报告位置；按症状选用局部运行或 Compute Sanitizer。性能修改前确认结果正确，固定输入、编译条件与计时口径，保留可比较的基线。
- 性能归因先明确慢的是端到端、提交/拷贝还是单个 kernel。按假设选择 Nsight Systems、Nsight Compute、编译资源和 PTX/SASS；无需为每个问题运行全套工具。静态指令、理论带宽和 occupancy 都不能单独证明实际瓶颈。
- 需要优化时做与假设对应的最小改动，复测正确性及受影响的性能指标，检查替代解释。工具、GPU 或计数器不可用时做可执行的静态检查，并明确哪些判断仍未验证。
- 实际开展实验时遵循目标项目的记录规范，保留命令、配置、原始输出和退出码；不改写旧证据。普通问答或局部低风险修改不额外生成实验脚本和日志。

## 交付与边界

默认用中文解释关键机制与结果，保留代码标识和必要英文术语。给出关键文件、函数、命令或日志位置，明确区分**事实、观察、推断、未知**；说明计时范围、验证结果和材料限制。用户只要求分析时不擅自扩大为实现或重测。

本 Skill 处理 CUDA 程序本身；纯 NCCL 源码学习优先使用 `nccl-study`。项目路径、构建命令、兼容性和产物归属以当前 `AGENTS.md` 及目标项目文档为准，不在此复制一份易过期的规则。
