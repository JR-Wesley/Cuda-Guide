# 如何记录一次优化实验的推导与决策

每份 `analysis.md` 应能让读者从源码重新算出模型、从原始数据重新得出有限结论，并判断下一步实验是否能排除竞争解释。记录可复核的技术推导、实验决策和证据，不只保留最终性能表。

已完成阶段的补充分析标为“事后证据复盘”：它重建证据之间的关系，不冒充实验前的带时间戳预测。后续阶段先记录假设、控制变量和可推翻条件，再采集数据。原始记录中的源码快照可以证明当时采用的实现；后续文字不得替换原始命令、失败或不符合预期的样本。

## 1. 从代码得到可计算模型

先写清一个 lane、一个 warp、一个 block 和整个 grid 各做多少工作。把地址写为元素索引，再乘元素宽度变成字节；sector/bank 必须注明假定的访问宽度、对齐、活跃线程和重复地址。区分完整 warp 与尾部。

从循环范围计算逻辑 load/store 和算术次数，而不是把源码行数当指令数。写明编译器可能消除、合并或展开的部分。记录 `requested bytes`、唯一工作集、分配跨度和实际 DRAM bytes 之间的差别。例如复制的 `8N` 不会因 float4 自动减半；改变 stride 时逻辑字节不变，但 sector footprint 可以变大。

资源模型先列 threads/block、registers/thread、shared/block，写出驻留 block 的候选限制。简单除法只给上界，分配粒度会收紧它；Runtime occupancy API 给理论驻留量，NCU 的 achieved occupancy 才是运行期指标。grid 小于可用 SM 时，单 SM 资源上界也不能保证整个设备填满。

## 2. 提出能被否定的假设

不要只写“优化应该更快”。写成：“在固定 N、工作量和计时范围下，把 X 从 a 改成 b，预计 Y 指标变化；若 Z 出现，就需要否定或缩小这一解释。”

至少列一个竞争解释和一个区分实验。例如 tiled→padded 同时改变 bank 映射和 shared 容量；若驻留量也下降，性能变化不能仅用 bank conflict 解释。向量化同时改变单线程工作和 grid，需要报告这些派生变化。

## 3. 按证据层级验证

| 证据 | 能回答什么 | 不能单独证明什么 |
| --- | --- | --- |
| CPU reference、边界与 sanitizer | 本次输入的结果与所检查的内存/同步行为 | 所有输入正确，或实现更快 |
| PTX | 虚拟指令和地址空间，前端是否表达了预期操作 | 最终物理寄存器、真实访存数量 |
| ptxas、SASS、resource usage | 最终指令形式、静态资源和 spill 报告 | 动态执行次数、cache hit 或 stall 比例 |
| 未插桩原始计时 | 指定范围内本次样本的分布 | 具体硬件瓶颈、普遍收益 |
| Nsight Systems 时间线 | kernel/copy/API 的先后、间隙、实际重叠 | 每个内存层的流量、bank conflict |
| Nsight Compute | 当前工具所支持的计数器与资源/调度证据 | 未插桩的绝对耗时、超出采样范围的行为 |

每次调用工具写明要解决哪个歧义。先查询当前工具支持的指标；工具缺失保留 Not Tested。不要用已经知道的总时间反复代替尚缺的机制指标。

## 4. 从结果反推，但保留多解

先检查模型与测量是否同单位、同范围、同输入。如果时间远高于字节/带宽估计，可能是额外流量、低并行度、依赖链、同步或提交间隙；单个时间不能唯一反演这些量。

可以计算无量纲比值来检验必要条件。例如相同数据量下 `tA/tB` 与预期流量比不符，说明“只由该流量决定”的模型不充分；相符也只是支持线索。使用实测 Copy 带宽预测其他 kernel 时，明确它是经验参照，不是硬件峰值或严格下界。

对于异常排序先检查方差、样本顺序和跨进程漂移。通过 A/B/B/A、同配置复测、增加问题规模或改变批量 K 检查竞争解释。若同配置漂移大于优化差异，结论应降级；不挑选有利样本，不把 P95 当标准差，不用单次 Min 宣称稳定收益。

## 5. 决定下一轮，而非只写结论

每一轮用下列顺序记录：

1. 入口：具体源码/参数，当前疑问。
2. 推导：公式、代入、假设、资源代价。
3. 干预：只改哪个因素，哪些量固定，哪些是无法避免的派生变化。
4. 观察：链接原始 CSV、命令、静态报告或时间线；写出与预测不一致之处。
5. 判断：已确认的事实、支持但未证实的解释、被反驳的过强结论。
6. 下一轮：能区分剩余解释的最小实验，以及预先约定的判定标准；标明已执行或待测。

优化不一定需要继续改代码。先修正计时口径、发现对照混杂或撤回不稳定的排序，也是有效的实验进展。已实现的案例可按下表阅读；各报告链接具体原始记录，区分采集前预测与事后复盘。
