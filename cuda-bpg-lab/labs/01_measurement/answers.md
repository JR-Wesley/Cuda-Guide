# Stage 1 参考答案

先完成 [问题与练习](exercises.md)。下面给出推理方向；涉及性能的答案必须补入自己的测量证据。

1. Add：12,582,912 B；Copy：8,388,608 B。教学假设 50 us 对应 251.65824 / 167.77216 GB/s。这些数值是公式演示，不是本机结果。输入读取和输出写入都必须计入。
2. 基线启动 512 线程；i=0..256 访问，257..511 不访问。grid-stride 设总线程数 T，任意 i 唯一分解为 `i=qT+r`，0≤r<T；线程 r 在第 q 轮处理它，因此没有漏写或多写。
3. 排序 `[1,2,3,7]`，Min=1，Median=2.5，P95=7。带宽与时间成反比，本项目 summary 的带宽是时间统计值的换算；不是独立对带宽样本取同名分位数。
4. 没有预定的“正确性能值”。K 增大可摊薄 Event 固定影响，但 host 提交仍可能跟不上设备；batch 平均可能包含空隙。增加 K 也不会消除频率、功率与调度变化。
5. 小工作集可能更多复用缓存，大工作集可能更依赖较慢存储层；同时 N 增大会改变并行度和固定成本占比。需 cache hit、sector、DRAM bytes/throughput 与时间线，不可由带宽曲线单独宣称命中率。
6. grid-stride 的循环控制、grid 波数、每线程工作与延迟隐藏都变了；SM 数的某个倍数没有普适最优值。固定 N/block/编译条件后观察，再用资源与调度指标区分解释。
7. 输出初始化为 NaN，CPU 比较拒绝非有限值，漏写应失败。确认失败返回值和无 CSV；原始成功记录不能被重写为失败记录或反之。
8. API 规定拷贝语义，不承诺具体内部实现。需要 Nsight 时间线、执行内核符号或其他真实执行证据；不能凭名字认定 copy engine。PTX 与 SASS 只显示本项目自定义内核，不一定包含 Runtime 内部实现。
9. `asm volatile` 约束编译行为，不是线程同步协议；launch 错误检查也不能建立数据依赖的 happens-before。本实验每个线程读只读输入并独占输出元素；H2D、kernel、D2H 在同一 stream 排序，host 在同步后读取结果。
10. 合格结论将“观测到某组时间”“可能由某机制解释”“某指标未测”分开，并给出设备、Toolkit、N、block、预热、K、样本数与证据链接。不能预先保证优化有收益。
